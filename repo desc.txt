# Nasiko repo overview (commit `70b4e74`)

**What it is:** a self-hosted platform for deploying and running AI agents. Users upload agents written in any framework or language that speak the A2A v1.0 protocol. Nasiko builds them, runs them, sends their LLM calls through its own router, reports cost and tokens, and gives them tools through an MCP gateway. It's a Rust workspace (edition 2024) with a React/Vite UI built into the server binary, licensed Apache-2.0.

**How to run it:** the README's "Quick Start: Docker only" (`cp .env.example .env`, set the secrets, `docker compose up -d`, then open `localhost:8080`). Contributors can instead run `just infra` and `just run`. **Neither is needed for the buildathon**; you only need Rust and `cargo run --example …`.

## llm-router request path (`handlers/chat.rs::chat_core`)

1. Read the request into the standard internal request shape (`ir/chat.rs`, OpenAI format; unknown fields are kept and passed through).
2. `resolve_routed_request` → `routing::route_model`, which tries in order: Pinned → CacheHit → SalienceGate (a small built-in text model that screens out small talk) → **Classify** (keyword/regex request type + Thompson-sampled tier; only at `cold_start`/`switch`, sticky on `continue`) → Config → Default.
3. Compression step (`compress.rs`, tool results only, keeps the prompt prefix stable for provider caching).
4. Brevity step (`brevity.rs`, a trailing system message, with a deliberately untouched comparison group).
5. `providers/fallback.rs` calls OpenAI, Anthropic, Gemini, Bedrock, OpenRouter, Azure or a custom provider.
6. Convert the response back to the caller's format, then log usage and savings without waiting for the result.

Settings live in `llm-router/src/config.rs` (`GatewayConfig::from_env`), the binary is `src/bin/llm-router.rs`, and the only example today is `examples/mint_token.rs`. **`classifier_eval.rs` is missing**, even though the brief says it ships.

## Repo conventions

- Zero warnings under `cargo check` and `cargo clippy`; run `cargo fmt`.
- Dependencies are declared once in the root `Cargo.toml` (`dep.workspace = true`).
- Extension points are traits passed around as `Arc<dyn Trait>`.
- Fail closed, stay deterministic, and keep libraries free of env reads and I/O.
- Unit tests must not touch the network, a database or Docker.
- Standards docs: `docs/CLEAN_CODE_GUIDE.md`, `ORGANIZATION.md`, `API_CONVENTIONS.md`.
- The committed `Cargo.lock` is stale, so a build rewrites it; keep that churn out of the PR.
